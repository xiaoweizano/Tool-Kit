项目概述

ToolKit 是一个本地优先的开发者工具箱，包含 21 个高频开发工具。项目采用 "一套代码，双输出" 架构：

  • Electron 桌面应用（产品本体）
  • 静态 Web 构建（在线过渡版本）

项目采用注册表驱动架构，添加新工具只需：

  1. 创建 src/renderer/src/tools/<id>/ 目录
  2. 在 register.ts 添加一行
  3. 在 transform.worker.ts 添加一行

开发工作流

1. 初始设置

git clone <repository-url> cd Tool-Kit pnpm install # 快速启动选项 pnpm dev:web # 仅浏览器（最快） pnpm dev # Electron 桌面 + HMR

2. 本地开发

浏览器开发

pnpm dev:web # 打开 http://localhost:5173/ # 环境：开发模式，自动刷新

桌面开发

pnpm dev # 打开 Electron 应用（带 HMR） # 可用原生操作系统集成

构建流程

Web 构建（静态输出）

pnpm build:web # 输出：dist/web/ # 用途：在线过渡版本（GitHub Pages/静态托管）

桌面构建

pnpm build:desktop # 输出：release/（Windows .exe，macOS .dmg） # 用途：生产桌面应用

构建产物位置

平台 文件路径 类型
Windows release/ToolKit-0.1.0-setup.exe 安装包
macOS (Apple Silicon) release/ToolKit-0.1.0-arm64.dmg 磁盘镜像
macOS (Intel) release/ToolKit-0.1.0-x64.dmg 磁盘镜像

测试工作流

pnpm lint # ESLint 代码风格检查 pnpm typecheck # TypeScript 类型检查 pnpm test # Vitest 单元测试

测试架构

  • 每个工具使用 golden-file 测试 确保转换保真度
  • 测试在 Web Worker 中运行，避免阻塞 UI
  • 转换函数为纯函数：输入字符串 → ToolResult 输出

GitHub CI/CD 工作流

CI 流水线（.github/workflows/ci.yml）

测试任务

  • 代码质量验证（lint、typecheck、tests）
  • 从 Git 标签自动更新版本
  • Node.js 22 环境配置

桌面构建任务

  • desktop-win：Windows 构建
  • desktop-mac：macOS 构建
  • 平台特定图标生成
  • 上传构建产物

Pages 部署

  • 部署到 GitHub Pages
  • 需要 pages:write 权限
  • 环境：github-pages

发布流水线（.github/workflows/release.yml）

  • 在 v* 标签推送时触发
  • 并行构建 Windows 和 macOS 产物
  • 发布到 GitHub Releases（草稿模式）
  • 使用国内镜像加速

部署说明

GitHub Pages 部署：
触发 main 分支推送，部署 dist/web 到 GitHub Pages，零配置静态托管。

Docker 部署

生产 Web 部署

Docker Compose 配置（deploy/docker-compose.yml）：

services:
  toolkit-web:
    image: nginx:alpine
    container_name: toolkit-web
    restart: unless-stopped
    ports:
      - "8080:80"
    volumes:
      # 首次部署前先在仓库根目录执行 pnpm build:web 生成 dist/web
      - ../dist/web:/usr/share/nginx/html:ro
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro

部署步骤

# 构建 Web 静态文件 pnpm build:web # Docker 部署 cd deploy && docker compose up -d # 访问 http://<server-ip>:8080
注意：首次部署前必须先运行 pnpm build:web 生成 dist/web 目录。

Nginx 配置说明

配置项 说明
Gzip 压缩 启用 Gzip 压缩，减少传输大小
静态资源缓存 5+ 年长期缓存
入口文件 no-cache 配置，支持客户端路由
只读挂载 安全配置，防止写入

工具开发工作流

添加新工具

必需的文件结构：

src/renderer/src/tools/<tool-id>/
├── index.tsx              # React 组件
├── transform.ts          # 核心转换逻辑
└── types.ts              # 类型定义（可选）

注册表配置

export const tools = [
  // ... 现有工具
  {
    id: 'json-parser',
    name: 'JSON 解析',
    icon: JsonIcon,
    route: '/tools/json-parser',
    component: lazy(() => import('./tools/json-parser')),
    capability: { offline: true }
  }
]

Worker 集成

// 在 transform.worker.ts 中添加工具
const transformRegistry = {
  // ... 现有工具
  'json-parser': jsonParserTransform
}

迁移与升级指南

版本升级

遵循语义化版本控制：

  • MAJOR：破坏性变更
  • MINOR：新功能，向后兼容
  • PATCH：Bug 修复，安全更新

升级命令

pnpm update # 查看 CHANGELOG.md 了解 breaking changes # 遵循迁移说明 pnpm test pnpm typecheck
警告：始终在开发环境测试升级后再部署到生产环境。

项目标准

TypeScript 规范

  • 启用严格模式
  • 禁止隐式 any
  • 接口优于类型别名
  • 错误类型使用判别联合

React 规范

  • 函数组件 + Hooks
  • TypeScript props 接口定义
  • 路由组件懒加载
  • 错误边界优雅降级

架构规范

  • 转换函数必须是纯函数
  • 单一职责原则
  • 需要时依赖注入
  • 适当使用不可变数据结构
